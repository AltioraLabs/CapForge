Turn static agents into autonomously evolving systems.

CapForge is enterprise capability-evolution infrastructure. When your agent encounters a task it cannot solve, CapForge discovers the capability gap, synthesizes type-safe code, validates it across a 5-level verification pipeline (including SMT formal invariants & mutation testing), governs safety, and promotes versioned, reusable capabilities — without retraining your foundation model.

CapForge IS vs IS NOT

IS: Capability acquisition, 5-level verification, hot-path optimization, versioning, and trust infrastructure. IS NOT: An orchestrator (LangGraph/CrewAI), a prompt engineering library, or a foundation model. CapForge sits directly underneath your agent systems as their runtime capability forge.

5-Minute Quickstart

Three straightforward moves: decorate a function with @capability → register and verify → execute inside an isolated sandbox with zero regression risk.

python 
from capforge import CapForgeClient, capability

# 1. Define a self-contained capability with typed parameters and verification tests
@capability(
    id="sentiment_analyzer",
    domain="nlp",
    risk_level="LOW",
    tests=[
        {
            "id": "t1",
            "inputs": {"text": "I love using CapForge for autonomous agents!"},
            "expected_keys": ["sentiment", "confidence"],
            "assert_expression": "output['sentiment'] == 'positive' and output['confidence'] > 0.8"
        }
    ]
)
def analyze_sentiment(text: str = "") -> dict:
    text_lower = text.lower()
    is_positive = any(word in text_lower for word in ["love", "great", "excellent", "fast"])
    return {
        "text": text,
        "sentiment": "positive" if is_positive else "neutral",
        "confidence": 0.95 if is_positive else 0.50
    }

# 2. Open embedded client (SQLite WAL + Docker/Subprocess Sandbox)
with CapForgeClient() as client:
    # Scan with CodeGuardian AST -> Run 5-level verification -> Promote to ACTIVE
    client.register(analyze_sentiment, promote=True)

    # 3. Execute safely in isolated sandbox
    response = client.execute("sentiment_analyzer", {"text": "CapForge makes agents self-healing!"})
    print("Execution Output:", response.output)
    print("Status:", response.status)
    print("Latency:", f"{response.latency_ms:.2f} ms")

    # 4. Export directly to OpenAI function calling format
    openai_tool = client.to_openai_tool("sentiment_analyzer")
    print("OpenAI Tool Name:", openai_tool["function"]["name"])

Core Architecture

Three-Plane Architecture

CapForge strictly decouples low-latency deterministic execution from asynchronous, resource-capped learning and synthesis:

Plane 1 — Execution Plane (Synchronous, Low-Latency) < 10 ms overhead

Serves production host agents (LangGraph, CrewAI, OpenAI Assistant, Cursor, Claude Desktop). Enforces runtime firewall security before delegating to isolated container sandboxes.

Host Agent Bridge
Capability Router
Runtime Firewall
Isolated Sandbox (Docker/Subprocess)
↓ Telemetry, spans, and novel execution failure patterns
Plane 2 — Control Plane (Governance & Trust Registry) Event Gateway & WAL

Maintains persistent state in SQLite WAL or PostgreSQL. Tracks SemVer versions, dependency DAGs, blast radius, cryptographic trust signatures, and SLA telemetry.

Capability Registry
HMAC / ED25519 Trust Chain
Dependency DAG & Blast Radius
Runtime Profiler (SLA Monitor)
↓ Unresolved capability gaps and optimization triggers
Plane 3 — Learning Plane (Asynchronous, Sandboxed) Job Worker Pool

Asynchronously executes heavy code synthesis, 3-pass AST self-repair, 5-level verification battery, PyO3 Rust transpilation, and mutation testing with zero impact on live agents.

LLM Code Synthesizer
3-Pass AST AutoRepair
5-Level Verification Pipeline
PyO3 Rust Transpiler
Security Invariant: Execution vs Learning Isolation

Production execution runs deterministic, read-mostly, and protected by the Capability Firewall. The Learning Plane operates in an unprivileged, isolated sandbox with zero access to production database credentials or host file access.

Core Architecture

5-Level Verification Pipeline

No synthesized or updated capability enters production without passing all 5 levels of the CapForge verification battery:

Level Gate Name Verification Objective & Mechanism
L0 CodeGuardian Security AST Static AST analysis prohibiting dangerous builtins (exec, eval, os.system), private network scanning, and unvetted imports.
L1 Structural & SMT Invariants Schema type conformance + Z3 / SymPy theorem proving for recursion termination, monotonicity, and output domain non-negativity.
L2 Functional Isolated Sandbox Executes capability inside an unprivileged Docker container or subprocess sandbox with strict CPU, memory, and timeout bounds.
L3 Property Fuzzing & Generalization Generates 50+ randomized boundary inputs (empty lists, negative numbers, extreme values) to prove robustness against unexpected inputs.
L4 Zero-Regression Battery Runs historical verification test suites across all prior versions to guarantee backward compatibility before promotion.
L5 Continuous Mutation Testing Injects deliberate AST mutations (comparison flips, boundary shifts) to ensure test suites kill > 80% of mutants.
Core Architecture

Closed-Loop Self-Repair Engine

When code synthesis fails during verification, CapForge activates a 3-pass automated repair loop without human intervention:

Pass 1: AST Heuristic Fixes

Deterministic regex and AST rewriting for missing imports, syntax errors, and indentation inconsistencies. Executed in < 5 ms.

Pass 2: LLM Reflection

Feeds compiler tracebacks, sandbox execution errors, and failed assertion logs back to the LLM for targeted code regeneration.

Pass 3: Schema Coercion

Analyzes input/output mismatches against ParameterSpec and applies automatic type-casting and dictionary key normalization.

python • auto-repair engine 
from capforge.verification.repair import AutoRepairEngine

# Initialize the 3-pass self-healing engine (AST fixes -> LLM reflection -> Schema alignment)
repair_engine = AutoRepairEngine(max_iterations=3)

# If sandbox evaluation fails:
repaired_capability, verif_result, report = repair_engine.repair_with_report(
    capability=failed_cap
)

if report.final_passed:
    print(f"Self-Repair Succeeded across {report.iterations_run} iteration(s)!")
    for step in report.steps:
        print(f"  * Pass {step.pass_number} ({step.strategy}): {step.description}")
else:
    print("Repair exhausted. Flagged for human review ticket.")

Trust Chain & Cryptographic Security

To prevent capability poisoning and supply-chain attacks, every capability in CapForge is cryptographically signed upon passing verification:

python 
from capforge.security.trust_chain import TrustChain

# Initialize Trust Chain with HMAC signing key (or set CAPFORGE_SIGNING_KEY in .env)
trust = TrustChain(signing_key="enterprise-signing-key")

# Sign a verified capability manifest at registration
signature = trust.sign(capability)
print("HMAC-SHA256 Signature:", signature.hmac_sig)

# Cryptographically verify tamper-evidence before execution
is_valid = trust.verify(capability)
assert is_valid, "Tamper detected: Capability code body was modified outside Control Plane!"

Integration Guide: Existing Multi-Agent Systems

If you already have a running multi-agent system — built with LangGraph, CrewAI, AutoGen, or a custom Python orchestrator — CapForge operates as your system's autonomous capability layer. It eliminates the fragile "static tool ceiling" where agents halt upon missing capabilities or unhandled parameter schemas.

How CapForge Enhances Existing Multi-Agent Swarms

You do not need to rewrite your agent prompts or replace your orchestrator. Your existing agents continue coordinating tasks. CapForge sits directly underneath your agent swarm: when any worker agent hits a missing tool or failure, CapForge discovers the gap, synthesizes type-safe code, validates it through the 5-level verification pipeline in an isolated sandbox, promotes it to the shared registry, and immediately equips all agents in the swarm with zero redeployment.

Multi-Agent Capability Evolution Topology Shared In-Memory / WAL Registry

Orchestrator delegates tasks → Worker Agent discovers gap or tool failure → CapForge synthesizes & verifies in sandbox → Verified capability promoted to shared registry → Instant reuse across all agents with zero latency overhead.

Step 2: Pre-Register Your Existing Domain Tools

If your project already has existing Python functions or tools, register them so CapForge's semantic gap detector knows they exist and avoids redundant synthesis:

python • register existing tools 
from capforge import capability

# Option A: Decorate existing functions directly
@capability(id="calculate_moving_average", domain="finance", risk_level="LOW")
def calculate_moving_average(prices: list[float], window: int = 20) -> dict:
    sma = [round(sum(prices[i-window+1:i+1])/window, 4) for i in range(window-1, len(prices))]
    return {"sma": sma, "latest": sma[-1]}

client.register(calculate_moving_average, promote=True)

# Option B: Register existing functions without modifying their source file
def legacy_volatility(returns: list[float]) -> dict:
    import statistics, math
    vol = statistics.stdev(returns) * math.sqrt(252)
    return {"annualized_volatility": round(vol, 4)}

client.register_function(legacy_volatility, id="calculate_volatility", domain="finance", promote=True)

Step 3: Handle Capability Gaps & Trigger Autonomous Evolution

When an agent is assigned a task for which no matching capability exists, query CapForge or invoke client.run_task(...) to trigger the autonomous evolution loop:

python • worker_agent.py 
def execute_or_evolve_task(client: CapForgeClient, task_description: str, task_inputs: dict) -> dict:
    # 1. Search for existing capabilities
    matches = client.search(query=task_description, threshold=0.30)
    
    if matches:
        best_cap, score = matches[0]
        # Found existing verified capability -> execute directly in sandbox (< 10ms)
        res = client.execute(best_cap.id, inputs=task_inputs)
        return {"status": "REUSED", "capability_id": best_cap.id, "output": res.output}
    
    # 2. No matching capability found -> Trigger autonomous acquisition
    print(f"Capability gap detected for: '{task_description}'. Forging new capability...")
    lifecycle_trace = client.run_task(
        task_intent=task_description,
        inputs=task_inputs,
        agent_id="risk_analyst_agent"
    )
    
    if lifecycle_trace.execution_result and lifecycle_trace.execution_result.status == "SUCCESS":
        new_cap = lifecycle_trace.acquired_capability
        print(f"Acquired and verified '{new_cap.id}' (v{new_cap.version}) in {lifecycle_trace.repair_iterations} repair iteration(s)!")
        return {"status": "EVOLVED", "capability_id": new_cap.id, "output": lifecycle_trace.execution_result.output}
    
    err = lifecycle_trace.execution_result.error if lifecycle_trace.execution_result else "Verification failed"
    raise RuntimeError(f"Capability acquisition failed: {err}")

LangGraph Integration

Integrate CapForge capabilities directly into LangGraph StateGraph workflows with automated self-healing and capability evolution fallback:

python • langgraph adapter 
from typing import TypedDict
from langgraph.graph import StateGraph, END
from capforge import CapForgeClient, LangGraphAdapter

class AgentState(TypedDict):
    task: str
    tool_inputs: dict
    result: dict | None
    error: str | None

client = CapForgeClient()
adapter = LangGraphAdapter(client)

# 1. Create a dynamic CapForge execution node for a registered tool
tool_node = adapter.create_langgraph_node("monte_carlo_var")

# 2. Create an autonomous evolution fallback node (synthesizes new capabilities if missing)
evolution_node = adapter.create_evolution_node()

workflow = StateGraph(AgentState)
workflow.add_node("execute_tool", tool_node)
workflow.add_node("evolve_capability", evolution_node)

# Route to evolution node if capability is not found, else END
workflow.set_entry_point("execute_tool")
workflow.add_conditional_edges(
    "execute_tool",
    lambda state: "evolve_capability" if state.get("error") == "CAPABILITY_NOT_FOUND" else END
)
workflow.add_edge("evolve_capability", "execute_tool")

app = workflow.compile()

Python-to-Rust PyO3 Transpiler

For computational hot-paths (Monte Carlo simulations, parser loops, math transformations), CapForge autonomously transpiles Python into native Rust PyO3 modules, achieving 20x–100x throughput gains without developer intervention:

python 
# Original Python computational hot-path (Latency: 18.4 ms)
def compute_var(portfolio_value: float, confidence: float, simulations: int) -> dict:
    losses = []
    for _ in range(simulations):
        ret = random.gauss(0.0005, 0.015)
        losses.append(-portfolio_value * ret)
    losses.sort()
    idx = int(confidence * simulations)
    return {"var_amount": losses[idx]}
// Auto-Transpiled PyO3 Rust Module (Latency: 0.38 ms • 48.4x Speedup)
use pyo3::prelude::*;
use rand_distr::{Normal, Distribution};

#[pyfunction]
pub fn fast_monte_carlo_var(val: f64, conf: f64, sims: usize) -> PyResult {
    let mut rng = rand::thread_rng();
    let norm = Normal::new(0.0005, 0.015).unwrap();
    let mut losses: Vec = (0..sims).map(|_| -val * norm.sample(&mut rng)).collect();
    losses.sort_by(|a, b| a.partial_cmp(b).unwrap());
    let idx = ((conf * sims as f64) as usize).min(sims - 1);
    Ok(losses[idx])
}

Troubleshooting & FAQ

What happens if no LLM API key is configured?

CapForge automatically falls back to deterministic AST templates and rule-based synthesis, allowing complete offline development and testing.

Can CapForge run without Docker installed?

Yes. When CAPFORGE_SANDBOX_DRIVER=auto, CapForge verifies Docker availability. If Docker is unavailable, it seamlessly falls back to secure subprocess isolation with resource constraints.

How does CapForge prevent regressions during upgrades?

Level 4 verification runs the complete historical regression test suite against any proposed version upgrade. If even a single test fails, the upgrade is blocked and automatically rolled back.

How do I migrate my existing agent tools into CapForge without rewriting them?

You do not need to rewrite your code. Simply decorate existing functions with @capability, or call client.register_function(my_func, id="tool_name", promote=True). CapForge inspects Python type signatures and docstrings to automatically generate parameter contracts and index them in semantic memory.

How do multiple agents share capabilities without database lock contention?

CapForge enables SQLite Write-Ahead Logging (PRAGMA journal_mode=WAL;) by default, allowing concurrent non-blocking readers across any number of agent threads or processes. For multi-node distributed agent clusters, set CAPFORGE_DATABASE_URL=postgresql://... to connect to a high-concurrency PostgreSQL cluster.

Can CapForge run fully offline with local LLMs (e.g. Ollama)?

Yes. Set CAPFORGE_LLM_PROVIDER=ollama and CAPFORGE_LLM_MODEL=qwen2.5:7b in your environment. CapForge will execute gap synthesis and self-repair reflection queries directly through your local Ollama daemon on http://localhost:11434 with zero external network dependencies.
